# 算力调度台（GPU Orchestrator）

一个面向个人 Linux GPU 服务器的算力调度台，提供浏览器网页版和 Windows 原生桌面客户端两种界面。通过 SSH 连接服务器，把状态探针和实验脚本放在用户自己的 ~/.gpu-orchestrator 目录下，不需要 root 权限。

## 已实现

- SSH IP、端口、用户名、密码连接；密码优先保存到本机系统密钥环。
- 新增或连接服务器时可读取本机 `~/.ssh/config`（支持 Include 与通配符默认值），从下拉一键填入主机、端口、账号和私钥路径；支持 SSH 密钥登录（IdentityFile，密码栏此时作为私钥口令）。暂不支持 ProxyJump/ProxyCommand 跳板连接。
- 服务器管理：每条记录使用独立连接 ID，不按 IP 去重；可保存相同 IP 的不同端口/账号连接，支持新增、编辑、删除和启用/停用监控。启动时自动连接已保存密码且开启自动连接的服务器；实验可单独指定目标服务器。
- 轮询 CPU、内存、主目录磁盘空间，以及每一张 NVIDIA GPU 的显存、利用率、温度、功耗和计算进程。
- 资源总览支持多服务器同时展示和滚动浏览；显卡卡片显示显存百分比，点击卡片可查看具体可用显存、进程、显存占用和运行时长。
- 基于 PyTorch CUDA 矩阵乘法的 FP16 Tensor 与 FP32 实测 TFLOPS；结果保存在本地状态文件。
- .sh 上传、工作目录、Conda 环境下拉选择、优先级、默认/低干扰/紧急执行级别、峰值显存门槛；低干扰级别可为每个实验设置忙卡利用率上限。
- 每个实验可选择一个或多个前序任务；默认无前序，只有所有前序任务成功完成后才会进入 GPU 调度。
- 每个实验都有不会复用的任务序号，支持删除未运行且未被其他任务依赖的历史任务；运行中的任务可从面板中断整个进程组。
- 调度规则：优先级数字越小越优先；同优先级按提交顺序；GPU 按 Tensor 基准速度优先；默认级别只使用满足显存条件的空闲 GPU，低干扰级别可共享最近 GPU 利用率峰值低于阈值的忙卡，紧急级别可在显存满足时共享忙卡。忙卡可用显存按最近采样中的显存占用峰值估算。
- GPU 忙卡判断的最近采样次数可在全局设置中调整，应用于所有服务器；显存峰值和 GPU 利用率峰值作为调度基准。
- 远程日志统一放在 ~/.gpu-orchestrator/runs/<experiment-id>/run.log，运行日志页面自动刷新最近 200 行；详情按钮按需读取完整日志。
- GPU 测试开始时会自动把最新 remote_agent.py 上传到目标服务器再执行；实验脚本在被调度到目标服务器时上传到对应的 runs/<experiment-id>/run.sh。
- 非零退出码标记失败；识别常见 CUDA OOM、退出码 137/139 后自动提高显存门槛，任务进入“等待显存”，下次满足条件后继续调度。
- 任务支持等待中、运行中、暂停中和已完成等状态，可单独暂停/恢复，也可以暂停全部任务并重新放回等待队列。
- 每台服务器独立调度；可单独设置主目录磁盘告警容量（默认 5GB），可用空间低于阈值时显示告警并暂停该服务器的任务调度。
- 客户端关闭不会终止远程任务；重新连接后会根据远程日志、退出码文件和进程状态同步执行结果。

## 启动

首次安装依赖：

    python -m pip install -r requirements.txt

启动网页版（推荐）：

    python app.py

然后浏览器打开 <http://127.0.0.1:8765/>。Windows 也可以双击 start_web.bat，它会启动服务并自动打开浏览器。网页版与桌面版共用 data/state.json 和后端调度逻辑，功能对等：多服务器管理、任务暂停/恢复/重排队/编辑/删除、前序依赖、暂停全部、调度暂停、GPU 测试和实时日志都可在浏览器完成。

启动原生桌面客户端（可选）：

    python desktop_client.py

Windows 也可以双击 start_client.bat。它会直接打开原生客户端窗口，不会启动浏览器或本地网站。注意网页版和桌面版不要同时运行，以免同时写 data/state.json。

桌面客户端使用深蓝侧栏与浅色工作区，资源卡片随窗口宽度自动排列。实验队列将选中任务操作与全部任务操作分组，表格支持横向滚动；运行日志支持拖动调整分栏宽度、滚动任务列表与日志输出。服务器管理、任务依赖、调度策略和日志等原有功能保留。

CPU、内存、显存与存储占用使用彩色比例条直观显示；侧栏保留并放大原 Logo。服务器设置、实验配置、GPU 详情、完整日志以及提示/确认弹窗共用统一样式，输入框、下拉框、数字输入框、复选框和按钮也保持一致。实验配置在宽窗口下分为基本信息和调度策略两栏，窄窗口下自动纵向排列，底部操作按钮始终可见。

GPU 详情使用与 Web 端类似的进程卡片，按显存占用排序，显示用户、PID、运行时长和完整命令。命令自动换行并支持选择及复制；窗口每两秒更新，保留滚动位置与未变更命令的文本选择。顶部仍显示显存占用/可用容量、利用率、温度和调度状态，进程显存合计与整卡显存占用分别展示。

详情窗口使用字体宽度与缓存计算命令换行高度，避免同步计算全部显示行阻塞界面；进程较多时分批创建卡片。重复点击同一 GPU 会复用已打开的窗口，关闭后取消刷新与待执行的布局任务。

客户端和 Web 端的资源卡片、GPU 测试卡片均有独立的「正常 / 屏蔽」按钮，点击即可切换。正常卡继续参与任务调度；屏蔽卡继续监测显存、利用率、温度和进程，但默认、低干扰、紧急三种调度级别均不会分配新任务到该卡。屏蔽不会终止或暂停已经运行的任务，手动 GPU 测试仍可使用。

设置保存在 `data/state.json` 的各服务器配置中，优先以 GPU UUID 标识显卡；没有 UUID 时按索引保存。重启、重新连接后仍生效，不同服务器的同号显卡互不影响。切换状态不等待 SSH 轮询，保存失败会显示错误并保留原状态。

验证客户端布局（使用临时目录和演示数据，不连接 SSH，不修改现有配置）：

    python scripts/verify_desktop_ui.py

检查 GPU 详情响应速度（长命令、窄窗口、多进程和重复点击）：

    python scripts/verify_gpu_detail_performance.py

检查客户端滚动响应（24 张 GPU、连续滚轮与小幅输入、滚动位置、实时刷新和关闭清理）：

    python scripts/verify_desktop_scroll_performance.py

验证 GPU 屏蔽、持久化、多服务器隔离、调度和 Web 按钮交互：

    python scripts/verify_gpu_scheduling.py
    node scripts/verify_web_gpu_scheduling.js

独立打开演示界面进行预览：

    python scripts/verify_desktop_ui.py --preview

首次连接会自动接受 SSH 主机指纹，适合个人内网原型；生产环境建议改为严格校验 known_hosts。远程主机需要可用的 python3 和 nvidia-smi。要执行 Tensor 测试，选择的 Python / Conda 环境需要安装 PyTorch CUDA 版本。

## 调度说明

峰值显存填 0 时，调度器不设置额外显存门槛；如果脚本出现常见 CUDA OOM 或 137/139 退出，会记录这次观察到的显存条件并将任务变为“等待显存”。自动判断来自脚本日志，不能保证识别所有自定义 OOM 文案；非零退出码的其它失败会直接标记为“执行失败”。

提交 `.sh` 脚本前，请参阅 [SH脚本执行规范.md](SH脚本执行规范.md)。该文档说明脚本格式、工作目录、Conda 环境、GPU 可见设备、日志和退出码要求。
